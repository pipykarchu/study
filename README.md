# 貅知识

浅粉与淡紫的双人学习花园。共用站点所有者账号，进入后选择 貔貅或 🐑 小羊；各自保存学习知识框架和进度。

## 已实现

- 默认以“对话学习”进入：左侧对话与模拟测试，右侧显示目标、七步进度、真实分数和下一步。
- 保留学习花园、知识框架、今日学习、项目练习、学习方法、资料与备份。
- AI 产品成长、Vibe Coding、FDE 前线部署工程师、通用学习四套起步框架；每个角色可独立选择。
- 首页和知识框架页可直接填目标、动机、验收作品、水平和学习时间；保存后准备 GPT 指令，由旁边对话生成六节点框架并通过站点工具回填。按钮不冒充模型回答。
- 六个知识节点的动手任务、过关标准、笔记与自主验收。
- 10 次学习安排、任务清单、专注计时器、自动保存笔记与复盘。
- 带个人目标和边界的六种 Claude 提示词，一键复制。
- JSON 完整备份/确认导入与 Markdown 框架导出。
- 七步闭环：框架与边界 → 抓核心 → 分段练习 → 主动回忆测验 → 项目应用 → 费曼复述 → 速查复习。
- 四套参考题库共 48 道题；逐题提交、判分、解析、错题复测与复习安排。完整六节点普通测验达到 80% 才完成测验阶段；短测和错题复测不会冒充完整通过。
- 阶段完成须留下自己的学习证据，AI 回复和消息条数不会自动算作“学会”。

网页保留无依赖的静态界面，本机学习和练习可用任意静态服务器打开。私人云端版通过 Worker + D1 保存记录，发布前运行下方构建：

```sh
python -m http.server 4173 --directory dist
```

## 两个角色与目标生成

网站仍只允许所有者的一个 OpenAI 账号登录；貔貅和小羊是内容分区，不是两个账号。首次进入会显示角色选择，顶部可以切换。貔貅继续使用已有数据，小羊从独立空间开始。切换角色会先尝试保存，再整页加载对应角色，目标、框架、节点笔记、测验、错题、同步版本和对话草稿都按角色隔开。貔貅保留原本地存储键和原云端行，旧记录无需手工迁移。

导出备份会标明角色，导入只能恢复同一角色；无角色标记的旧备份归原角色貔貅。清空也只影响当前角色。AI 写入工具必须提供读取上下文后得到的角色与方向，等待期间切换角色或方向会拒绝原操作。云端响应再次核对角色，避免迟到的响应写进别人的空间。使用同一登录账号的人仍可主动切换并查看两个角色；这不是彼此保密的独立登录权限。

在首页或知识框架页选择 Vibe Coding、FDE 等方向，直接填写目标，点“保存并准备 GPT 生成”，再将指令发给旁边的 GPT / Codex。模型先核对角色和方向，生成后调用 `study_apply_framework` 写回六个节点、练习、验收和三份边界。写错角色或方向会被拒绝。生成不会增加完成进度；更新框架会保留原笔记、清除节点自测勾选，原测验仍是方向参考题，不等于为生成主题重新出题。

FDE 起步路线参考[官方公开职责](https://openai.com/careers/forward-deployed-engineer-%28fde%29-seattle-seattle/)，覆盖业务指标、需求范围、集成、评测、部署可靠性和交付采纳；本站不是官方课程或认证。

## 数据与能力边界

学习目标、笔记、七步证据、模拟测试和错题先保留在当前浏览器，登录核验后通过同源接口同步到私人 D1 数据库。按平台稳定用户 ID 保存，每次请求还核对预先验证的所有者邮箱哈希。不会上传 Codex 密码、登录令牌或聊天内容。完整 JSON 备份包含两套学习记录，兼容旧版导入；题库成绩不代表能力认证。不要把个人学习备份或密钥提交到源码仓库。

云端 Sites 继续仅站点所有者可访问。另一台电脑登录同一账号、打开相同网址并选择相同角色，等待左下角显示“学习记录已同步”即可恢复。旧浏览器第一次连接时会迁移已有记录；两处都有不同内容时先保留本机副本，再由用户选择“使用云端”或“保留本机并上传”。多电脑同时编辑采用版本锁，冲突不会静默覆盖。离线可以继续练习，回网后重试；离开前请确认已同步或导出备份。云端版与本机版是不同网址，本机版不自动跨域连接云端，迁移可使用 JSON 备份。

## 在别的电脑的 Codex 里使用

1. 登录自己的 Codex 账号，在桌面内置浏览器打开私人网站。
2. 确认左下角的云端同步状态，并检查地址栏的“站点工具”。需要支持该功能的应用版本与账号设置。
3. 在旁边的 Codex 对话中说：“读取本站学习目标，先问我一个问题，等我回答后再记录结果。”
4. 站点提供 10 项 WebMCP 工具：读取上下文、切换方向、保存目标、保存边界、记录证据、记笔记、开始测验、提交答案、读错题和回填生成框架。写工具在本人校验和云端保存成功后才报告成功；出错时会区分本机草稿与云端保存。

站点工具通过 `document.modelContext` 注册，关闭网页后不可用。不需要把 Codex 登录凭据放进网站，也不需要让原来的电脑一直开机。普通浏览器可以学习和测验；AI 回答在 Codex 对话里进行。

## 可选：本机网页内直接问答

电脑已安装并登录 Codex 时，在本机运行：

```sh
node local/server.mjs
```

已完成本人绑定的 Windows 电脑可以双击根目录的 `启动貅知识.cmd`，然后打开 [本机学习版](http://127.0.0.1:4175/#coach)。电脑和本机服务需要保持开启。

本机版的“对话学习”页使用本机已有登录，不需要把订阅凭据或 API Key 填进网页。优先使用本机配置的模型；如果当前账号的可用列表不包含该模型，仅给本学习会话选择该账号可用的默认模型，不修改全局配置。提问可选择携带学习目标与边界；支持流式回答、停止回答和新对话。对话暂留在当前网页标签页，不会自动继承桌面应用中已有聊天。学习笔记和聊天是不同记录，完整学习备份不包含聊天内容。

本机服务只监听 `127.0.0.1`，限定同源请求，校验请求令牌并限制单任务；通过 stdio 使用官方 Codex App Server。学习对话采用只读、禁止自动执行操作的权限配置。登录信息留在本机，未复制到云端。云端版提供本机入口，不会自动跨域连接你的电脑。

本机问答进一步校验已预先确认的所有者：只接受与 `.local-runtime/owner.json` 中邮箱 SHA256 一致的 ChatGPT 登录。该文件不进入源码或部署包；当前安装已绑定平台验证过的站点所有者，其他电脑需要由本人完成独立绑定，不能把首次任意登录自动当成所有者。每次提问重新核对身份，登录变化会停止正在回答的内容并作废会话；正常授权刷新也可能需要开新对话。

网站不收集、保存或转发 Codex 密码。云端访问使用 OpenAI 官方登录和 Sites 私有允许名单；本机服务拒绝跨站请求、错误 Host、缺少校验令牌的写请求、目录越界和超限请求。没有任何网站能保证绝对不被攻击；这些限制也不能防御已控制同一 Windows 用户或能修改本机文件的人。

Windows 上会优先保留显式代理环境；未设置时，本机连接器会把已启用的系统代理传给 Codex 子进程，并绕过本机地址。不会修改系统代理、全局 Codex 配置或父进程环境。

官方说明：[Codex App Server](https://learn.chatgpt.com/docs/app-server)。本地应用可使用本机登录；本项目没有把既有登录凭据转作云端托管服务凭据。

## 检查

```sh
node --check dist/app.js
```

云端构建与产物检查：

```sh
node scripts/build-cloud.mjs
node scripts/validate-cloud-artifact.mjs
```

Sites 部署配置在 `.openai/hosting.json`，D1 逻辑绑定为 `DB`。初始 schema-only migration 在 `migrations/`，发布使用 `drizzle/` 中的同一 SQL 和 journal。Worker 会嵌入 `dist/` 的页面资产，构建后须重新检查嵌入资产一致性。运行时 `STUDY_OWNER_EMAIL_SHA256` 通过 Sites 环境变量配置为已验证所有者的哈希，不写入源码或客户端。接口采用同源 JSON、2 MB 限制、服务端数据校验和乐观版本锁。

真实浏览器中的工具发现与调用尚未验收；用户已明确允许先发布并保留此说明。DOM、HTTP 和 SQLite 集成测试不能替代这项检查。

貔貅头像使用本机 tuzi-image 入口生成，采用与小羊协调的软萌立体小动物风格，透明头像无损编码为 WebP，存放在 `dist/pixiu.webp`。原角色数据标识保持不变。
